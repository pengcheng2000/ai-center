# 全员 AI 能力提升平台

> 面向企业员工的 **AI 学习、资讯、实践沉淀与运营治理中台**。平台不以展示为目标，而以“学习能力建设、可信资讯、实践复用和责任可追溯”为持续运营闭环。

## 当前交付状态

当前工程已覆盖员工工作台、学习中心、AI 资讯中心、实践社区、个人画像与 Workspace，以及多供应商模型治理、学习内容运营、AI/人工审核和资源生命周期管理。学习中心已新增文档、视频与受控模型实操资源能力；AI 审核员可从已启用的供应商与模型目录中级联选择审核模型，并在保存前执行受控“测试连接”。员工还可在 Skills 广场按关键词/分类/评分查找、分享、评论、评分、下载和复用企业 Skills，并在个人中心查看自己的投稿与下载资产。运营管理员可直接批量导入已核验的 Skills ZIP 与 `SKILL.md`，按批次配置后进入审核或上架。平台现提供外部 Agent 内容导入能力：Agent 可通过可安装 Skill 将经授权的文章、图片、课程资源和 Skills 整理为待审核草稿。数据库迁移已包含至 `0018_zippy_grim_reaper`；本地回归基线为 **16 个测试文件、87 项测试与 TypeScript 检查通过**。

## 产品与技术架构

```text
员工端（工作台 / 学习 / 资讯 / 社区 / Workspace）
                  │
React 19 + Vite + Wouter + TanStack Query + tRPC Client
                  │
Express 4 + tRPC 11（员工保护路由 / 管理员路由 / 审计边界）
        ┌─────────┼─────────┐
        │         │         │
 MySQL/TiDB   Manus OAuth   Manus Forge（LLM / 对象存储）
 Drizzle ORM   角色鉴别       审核、附件签名访问
```

项目的关键安全边界是：员工私有画像、Workspace、收藏和阅读关系以当前身份为范围；运营配置、审核记录、删除恢复及内容维护仅允许管理员调用；供应商密钥只保存 **Secret 别名**，不把原始 API Key 写入业务数据库。

## 快速开始

开发环境需要 Node.js 22+、pnpm 10+ 与 MySQL/TiDB。复制或配置部署环境提供的变量后，在项目根目录运行：

```bash
pnpm install --frozen-lockfile
pnpm drizzle-kit migrate
pnpm test
pnpm check
pnpm dev
```

| 命令 | 用途 |
|---|---|
| `pnpm dev` | 以开发模式启动 Express/Vite 服务。 |
| `pnpm test` | 运行 Vitest 单元、路由和治理契约测试。 |
| `pnpm check` | 运行 TypeScript 类型检查。 |
| `pnpm build` | 构建前端和 Node 服务端产物至 `dist/`。 |
| `pnpm start` | 以生产模式启动构建产物。 |
| `pnpm drizzle-kit generate` | 依据 schema 生成待审阅的迁移。 |
| `pnpm drizzle-kit migrate` | 应用已提交且经审阅的迁移。 |

> **注意：** 不要使用 `pnpm db:push` 作为生产数据库的默认迁移方式；它会先生成再直接迁移，缺少人工审阅关卡。

## 运营使用说明

### 学习内容如何维护

管理员进入 **运营管理 → 学习内容运营**。先建立草稿学习路径，再配置路径中的课程、资源 URL、标签、先修关系和顺序；补齐业务负责人、内容负责人、复审日期、版本号与更新说明后，将路径和课程分别发布。员工端仅会读取已发布课程；资源过期时应归档而不是物理删除，以保留学习与运营历史。

课程资源台账支持三类资源：**文档型**可受控采集公开 HTML/Markdown/纯文本 URL，并上传 PDF、Word、Markdown、文本或图片；**视频型**可维护 MP4/WebM 或外部视频 URL，员工端支持 0.75×–2× 倍速、时间戳评论和轻量弹幕叠层；**实操型**可配置固定教学指令，员工通过受控模型实操台获得结果。实操不执行代码、不调用外部系统，单人单任务每日上限为 5 次，结果仅对该学习者可见。

建议采用“能力路径—任务课程—资源版本—学习数据—季度复盘”的维护节奏。路径负责人负责业务目标，内容负责人负责课程和资源质量；运营台中的路径覆盖、资源缺口、复审风险和平均完成率用于每月发现维护优先级。

### AI 资讯如何维护

管理员在 **运营管理** 添加或编辑 RSS 来源，并使用“同步”拉取资讯。导入条目会进入待审核队列，可由批量 AI 预审过滤高置信低质量内容；高风险、低置信或失败条目保留给人工处理。AIHOT 的“精选全文”源支持内容升级：允许内联正文的条目显示全文，其余保留摘要和原文入口。

资讯中心按“今日、近 7 天、近期、历史”组织，并显示运营精选、全文解读、聚合阅读人数和收藏次数。阅读计数是员工与资讯的唯一关系聚合，平台不会在前端展示阅读者身份。

### 审核、删除和恢复

AI 审核仅在低/中风险且达到审核员阈值时直接通过或拒绝；高风险、关键风险和低置信结果一律进入人工复核。管理员删除资讯时采用软删除，并必须提供原因；操作人、时间和原因都会进入审核记录。恢复后的资讯先回到人工复核，不会绕过审核直接公开。

### 审核模型与应用中心如何维护

管理员在 **运营管理 → AI 审核员 → 配置** 中选择供应商和已启用模型后，可点击“测试连接”。对于 Manus 受管模型，服务端先核验实时模型目录，再发送一次不带工具的最小文本请求；测试成功才把供应商标记为已验证。外部供应商若仅登记了 Base URL 与密钥别名，会被明确提示为“尚未完成受管网关接入”，可保留配置但不能启用为实际审核员，避免误把目录记录当成可执行连接。

管理员在 **运营管理 → 管理应用入口** 中添加公司 Agent 平台、专利小匠或其他工具。每个入口均可维护名称、说明、HTTP(S) URL、分类、员工可见范围、排序与启停。应用中心不保存第三方账号或密钥；员工登录后从顶部“应用中心”访问已启用且非管理员专属的入口。

### Skills 广场如何分享和审核

员工从 **Skills 广场 → 分享 Skills** 提交名称、唯一标识、分类、标签、版本、用途说明、`SKILL.md` 文本、使用方法与 `.zip` 安装包。投稿会先处于待审核状态；员工可查看自己的投稿状态与审核意见，但只有审核上架的 Skills 才会出现在公共目录。

管理员在 **运营管理 → 治理 Skills 投稿** 审阅详情，核对 `SKILL.md`、使用说明、安装包和外部依赖后，填写依据并上架、退回或下架。详情页向已授权访问者提供受控下载和可复制的自然语言安装指令，例如“安装 Skills「专利检索助手」，下载链接：……”。下载链接为短期签名 URL，失效后需重新进入详情页取得；平台不解压或执行投稿包，不应上传密钥、Cookie、个人数据或未经批准的破坏性脚本。

员工可以按名称、唯一标识、用途说明或标签搜索，并按已上架分类过滤、按最新或评分优先排序。每位员工对同一已上架 Skills 只能维护一条评分与评论，可更新或删除自己的反馈；详情页仅展示聚合评分和公开评论，不展示谁下载过。成功下载会计入当前员工自己的“个人中心 → 我的 Skills”，其中分别列出投稿/发布状态与历史下载次数，其他员工无法查看该资产列表。

## 外部 Agent 自动内容入库

工程内置的 `agent-skills/ai-empowerment-content-import/` 可安装到你的 Agent。该 Skill 会指导 Agent 将已明确授权的文章链接或资源整理为平台 Markdown 图文草稿：先读取正文，再经平台接口托管图片/附件，最后提交 `news`、`course_material` 或 `skill` 草稿。它不会绕过来源访问控制、直接发布内容、直接写数据库或执行文章/Skills 包中的代码。

管理员后续只需在 **运营管理 → Agent 内容导入** 签发一次性显示、按内容类型收窄且可撤销的令牌；将正式域名和令牌作为 Agent 私密配置中的 `PLATFORM_BASE_URL` 与 `AGENT_IMPORT_TOKEN`。具体 HTTP 调用、JSON 模板、媒体占位写法和草稿审核步骤详见 [`AGENT_CONTENT_IMPORT_GUIDE.md`](./AGENT_CONTENT_IMPORT_GUIDE.md) 与 Skill 内的 `references/api.md`。本轮按你的要求**未执行生产环境真实导入**。

## 管理员直接导入 Skills

管理员通过 **运营管理 → 治理 Skills 投稿 → 直接导入 Skills** 可一次选择最多 10 个企业 ZIP 安装包，并分别上传 `SKILL.md`、维护名称、唯一标识、说明、分类、标签、版本与使用方法。默认策略为待审核；只有管理员已确认包内容、依赖和权限时才可选择直接上架。每个条目记录管理员来源、同批次标识、导入说明、操作人和时间，且仍不执行 ZIP 内任何内容。完整操作、文件限制和发布边界请阅读 [`SKILLS_DIRECT_IMPORT_GUIDE.md`](./SKILLS_DIRECT_IMPORT_GUIDE.md)。

## 贡献与变更规范

任何功能变更应遵循以下顺序：更新 `drizzle/schema.ts`（如涉及数据）→ 生成并审阅迁移 → 应用迁移 → 修改服务端与前端 → 补充 Vitest 测试 → 运行 `pnpm test && pnpm check`。涉及发布内容、审核、权限、删除、员工个人数据或外部来源时，优先选择可恢复、可审计、最小权限的设计。
